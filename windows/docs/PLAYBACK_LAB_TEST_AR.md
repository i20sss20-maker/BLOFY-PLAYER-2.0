# مختبر BLOFY Windows — تشغيل HLS / DASH (للتجارب فقط)

**هذا العمل فرع تطوير مستقل، وليس تحديثًا لنسخة Windows المنشورة.**

## المتوفر الآن
- مشغل Windows الحالي يستخدم **WPF + LibVLC 3.0.24**.
- أضيف خيار داخل الإعدادات في **نسخة Debug فقط**: «🧪 اختبار HLS / DASH».
- يمكن إدخال رابط وسائط اختباري آمن `.mpd` أو `.m3u8` أو `.ts` أو `.mp4`.
- تقبل التجربة روابط HTTPS العامة مع الحفاظ على Query الخاص بالرابط، أو HTTP من الجهاز المحلي (localhost) فقط.
- لا تُخزَّن الروابط في إعدادات التطبيق أو المكتبة.
- لا تضاف قنوات جديدة إلى أي كتالوج ولا يُعاد بث الفيديو للآخرين.

## التجربة العملية
1. افتح صفحة GitHub Actions في الفرع التجريبي بعد اكتمال نجاح CI.
2. من Artifacts نزّل `BLOFY-Windows-DEBUG-Playback-Lab-x64`.
3. فك الضغط داخل مجلد اختبار مستقل عن نسخة BLOFY المثبتة. ملف Debug غير موقع كتحديث تجاري.
4. افتح التطبيق من المجلد التجريبي فقط، ثم الإعدادات ← «🧪 اختبار HLS / DASH».
5. أدخل رابط فيديو `.mpd` أو `.m3u8` معروف ومصرح باستخدامه.
6. تحقق من الصورة والصوت والتقطيع والانتقال من المشغل، وقارن بسلوك إصدار المستخدم.
7. لا ترسل روابط اشتراكاتك أو Tokens ضمن صور أو سجلات عامة.

## حدود هذه التجربة
- نجاح CI يعني صحة البناء والاختبارات المحددة، **وليس ضمان تشغيل الفيديو على Windows الحقيقي**.
- مشغل LibVLC الحالي ليس تكاملًا صالحًا لفك حماية Widevine أو استخراج المفاتيح.
- لا يوجد دعم Widevine معتمد في Windows حاليًا. لإضافته نحتاج محرك/CDM يدعم إصدار التراخيص الأصلية وصلاحيات التشغيل.
- لا تستخدم القنوات المشفرة أو المحتوى غير المصرح لك به، ولا تعمل إعادة بث في هذه التجربة.
- لا تدمج فرع التجارب أو تنشر Setup إلا بعد اختبار المستخدم والموافقة.
