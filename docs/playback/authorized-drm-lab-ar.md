# مختبر BLOFY لتشغيل HLS وDASH وWidevine المرخّص

**الحالة:** تطوير تجريبي داخل Pull Request، وليس تحديثًا منشورًا للمستخدمين.

## ما الذي تغير؟
- تمت إضافة مشغل Media3 DASH المطابق لإصدار مكتبات التشغيل الحالي `1.6.1`.
- أصبح التطبيق يتعرف صراحة على ملفات `.mpd` للبث DASH، وعلى `.m3u8` حتى للأفلام والحلقات.
- استمر دعم بث TS كما كان سابقًا، مع المحافظة على روابط المحتوى الأصلية ومعاملاتها.
- أُضيف خيار اختياري لتقديم عنوان خادم ترخيص **Widevine HTTPS** من جهة مصرح لها أثناء تشغيل فيديو واحد. عند تغيير القناة أو المحتوى تُصفّر إعدادات الترخيص السابق.
- أُضيفت اختبارات آلية للتحقق من الامتدادات وروابط الترخيص الصحيحة وغير الصحيحة.

## ما الذي لم يتغير؟
- لا توجد قنوات جديدة أو قوائم IPTV مقرصنة.
- لم يُضف استخراج مفاتيح DRM ولا تجاوز اشتراك أو حماية.
- لم تُنشر نسخة Android أو Windows؛ ولم يتغير سيرفر الإنتاج.
- تشغيل Shaka داخل Chrome لا يثبت نجاح Widevine داخل تطبيق Android نفسه.

## كيف نجري تجربة فعلية؟
1. ننتظر نتيجة اختبار GitHub Actions للبناء وUnit Tests وLint.
2. نثبت APK تجريبيًا على جهاز اختبار بعد نجاح البناء، **وليس على جهاز المستخدم النهائي**. نسخة Debug تحمل توقيعًا مختلفًا عن إصدار المتجر، لذا لا تحاول تثبيتها فوق نسختك الرسمية ولا تحذف التطبيق الرسمي.
3. من **الإعدادات ← 🧪 مختبر التشغيل** (يظهر في Debug فقط)، ندخل رابط بث DASH أو HLS لاختباره. يمكن ترك خانة الترخيص فارغة للمحتوى غير المحمي.
4. نجرب HLS للأفلام والحلقات وبث TS المباشر؛ نتأكد أن التقديم والترجيع وتغيير القناة لا ينكسر.
5. نجرب عينة Widevine اختبارية مع **رابط ترخيص HTTPS مسموح**، عبر التكامل الداخلي في `PlayerActivity`.
6. نتأكد من أن الترخيص السابق لا يُستخدم تلقائيًا في قناة أخرى.

## ملاحظة Windows
لم يظهر كود Windows/Electron قابل للتعديل ضمن المستودعات المرتبطة التي تمت مراجعتها. لذلك عمل Android هنا لا يعني أن Widevine صار شغالًا في نسخة Windows. نحتاج سورس تطبيق Windows أولًا وتحديد محرك العرض المستخدم قبل تغيير بنية التشغيل.

**المستند التقني والـIntent الاختياري:** `docs/playback/authorized-drm-lab.md`.
