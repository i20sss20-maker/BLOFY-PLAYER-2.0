## أدلة ناجحة

- استُخرج APK المنشور من ناتج البناء وطابقت بصمته أصل GitHub المنشور.
- API المستهدف والمُستخدم للبناء: 36؛ الحد الأدنى: 23.
- فحص ELF ومواضع الملفات داخل APK: مكتبات FFmpeg الأربع محاذاة إلى 16 KB، ومنها arm64-v8a وx86_64.
  الدليل في `rc0745-apk-audit.json` ويُعاد إنتاجه بالأداة `tools/audit_published_apk.py`.
  لا يثبت ذلك اختبار تشغيل فعلي على جهاز 16 KB أو محاذاة ملفات split الناتجة عن Google Play.
- [البناء الموقّع والترقية](https://github.com/i20sss20-maker/BLOFY-PLAYER-2.0/actions/runs/34780909446)
  نجح بنفس الشهادة، وبنفس بايتات المكتبات الأصلية، مع حفظ الهوية والقوائم المشفرة والمفضلة والاستئناف عند الترقية.
- [اختبارات Android](https://github.com/i20sss20-maker/BLOFY-PLAYER-2.0/actions/runs/34780541829)
  تشمل الاختبارات المحلية وlint والبناء وفحص استعلامات كتالوج 200 ألف سجل.
- [واجهات الهاتف والتلفزيون](https://github.com/i20sss20-maker/BLOFY-PLAYER-2.0/actions/runs/34780541796)
  اجتازت 9 اختبارات ببيانات وسيرفر صور تجريبيين؛ هذا ليس اختبار تشغيل اشتراك حقيقي.
- [اختبارات خدمة الإنتاج](https://github.com/i20sss20-maker/BLOFY-PLAYER-2.0/actions/runs/34781753365)
  تشمل PostgreSQL والجلسات وعزل قوائم جهازين ونشر الإصدار وصفحة Downloader.
- `/health` أعاد 200 مع جاهزية قاعدة البيانات وتشفير القوائم والإصدار الصحيح. لم تُظهر خدمة Vercel
  مجموعات أخطاء تشغيل في نافذة 24 ساعة وقت الفحص؛ هذا ليس إثباتًا لغياب جميع الأخطاء.
- النسخ الاحتياطي السحابي ونقل بيانات Android بين الأجهزة مستبعدان صراحة من بيانات التطبيق الحساسة.
- لم يجد البحث في مصدر التطبيق الحالي أنماط مفاتيح GitHub/AWS/Google أو مفاتيح خاصة.
  هذا بحث بأنماط محددة، وليس فحص تاريخ Git الكامل أو تأكيدًا بعدم وجود أي سر.

## عيوب أصلحها فرعا المراجعة

| العيب | المعالجة | التحقق |
|---|---|---|
| سجل PlaybackDiagnostics يتراكم بلا حد، وتحديثه بعد clear قد يتسابق | حد فعلي 100 سجل ومزامنة التحديث والمسح؛ تجاهل أحداث الجلسات المحذوفة | جلسة طويلة، أحداث متأخرة، تحديثات ومسح متزامنان |
| تراكم إرسال التشخيص عند بطء الشبكة | طابور محدود 16 مهمة وانتظار كلي محدود؛ إسقاط الأقدم دون تشغيله على واجهة المستخدم | حجب مهمة وإغراق الطابور ثم وصول أحدث مهمة |
| عملاء خدمات BLOFY يتبعون التحويلات؛ ترويسات سحابة الملف قد تنتقل لوجهة أخرى | منع التحويلات في عملاء التفعيل والقوائم والاشتراكات والسحابة والتشخيص | خادمان محليان يثبتان عدم وصول الطلب أو رمز الجهاز للوجهة الثانية |
| مسار إنشاء جلسة المشتركين لا يحتسب تخمين رمز الجهاز ضمن القفل الدائم | احتساب المحاولات داخل معاملة وقفل صف الجهاز وحدود طلبات؛ لا تُصفّر المحاولات بعد نجاح عادي | اختبار ذاكرة واختبار PostgreSQL بعدة عاملين، وعقد الجلسة الحالي |

هذه الإصلاحات ليست تلقائيًا جزءًا من APK rc07.45 المنشور. حالة دمجها ونشرها موثقة في طلبات الدمج.
لم تتغير محركات التشغيل أو Media3 أو FFmpeg أو روابط البث أو الثيم.

| عالٍ — Google Play | APK يطلب REQUEST_INSTALL_PACKAGES ويستخدم تحديثًا ذاتيًا خارج Play | بناء مخصص للمتجر بلا تثبيت APK؛ تحديثات Play أو رابط صفحة المتجر. لا ترفع APK/AAB الحالي كما هو |
| عالٍ — الدفع | شاشة انتهاء التجربة تدعو للتجديد بالباركود، ويوجد مسار checkout خارجي في SubscriptionClient | اختيار Play Billing أو نموذج استهلاك فقط، أو برنامج استثناء مؤهل فعليًا؛ مراجعة جميع الروابط والباركود والصفحات التابعة |
| عالٍ — الخصوصية | لا توجد سياسة خصوصية مرتبطة داخل التطبيق ولا مورد منشور مكتمل؛ بيانات تفعيل وتشخيص وقوائم تُعالج | سياسة عامة باسم المطور/التطبيق وجهة اتصال فعلية، الإفصاح والاحتفاظ والحذف، نموذج Data safety مطابق للكود |
| عالٍ — الخدمات | GET /api/v1/cloud/profile وGET /api/v1/subscriptions/plans أعادا 404 في الإنتاج؛ التطبيق يحتوي عملاء لهما | استعادة الخدمات المطلوبة انتقائيًا مع اختبارات، أو إزالة الميزات غير المتاحة من النسخة التجارية. لا تنسخ خدمة runtime القديمة فوق main |
| عالٍ — تشفير الاتصال بقاعدة البيانات | إعدادات pg في عدة ملفات تضبط rejectUnauthorized:false | التحقق من شهادة مزود قاعدة البيانات وCA واتصال staging ثم فرض التحقق؛ لا نعلن توثيق TLS ناجحًا من مجرد /health |
| عالٍ — تعطل Keystore | ProviderSecretCipher.seal يعيد الصف الأصلي إذا فشل التشفير، وقد يكون نصًا صريحًا | منع حفظ أسرار جديدة دون تشفير مع رسالة قابلة للفهم، مع الحفاظ على البيانات القديمة وعدم مسح المفاتيح |
| تجاري | الهوية مرتبطة بالتثبيت؛ حذف البيانات أو التطبيق ينشئ هوية جديدة وتجربة جديدة | اعتماد طريقة استعادة الرخصة المدفوعة ومنع إساءة استخدام التجربة؛ لا تُستبدل بمعرّف عتاد خفي |
| خصوصية/متجر | توجد إزالة قائمة وتعطيل جهاز، ولا يوجد مسار واضح لطلب حذف كل بيانات الجهاز | تحديد انطباق حسابات Play وإضافة طلب حذف داخل التطبيق ومورد ويب مناسب؛ التعطيل ليس حذفًا |
| استقرار | الكراش المتقطع على جهاز المستخدم لم يتكرر بالمحاكي | اختبار النسخة النهائية على Honor ومستقبل Android TV مع سجل العطل عند حدوثه، وتشغيل طويل واتصال ضعيف |
| اعتمادات | FFmpeg مُثبت على n6.0؛ بقية الاعتمادات ثابتة في Gradle، وpg يستخدم نطاق إصدار | مطابقة نشرات الأمن مع الشيفرات/decoders المجمعة فعليًا وتوثيق قابلية الوصول. لا يوجد حكم بأن كل CVE في FFmpeg يصيب هذا البناء؛ أي تغيير محرك يخضع لتعليمات المالك |
| عمليات | لم يُختبر استرداد قاعدة بيانات الإنتاج من نسخة احتياطية، ولم يُفحص Play Console | تجربة استعادة في بيئة معزولة، توثيق مفاتيح التوقيع، حساب المتجر والتحقق والمختبرين وبيانات المراجعة |

HTTP متاح لمصادر المستخدم مع التحذير الحالي، لذلك لا يصح إعلان أن **كل** بيانات الاتصال مشفرة أثناء النقل.
مصادر FFmpeg وشروط بناء LGPL محفوظة في ناتج الإصدار، لكن إسناد تراخيص الاعتمادات داخل المنتج يحتاج مراجعة مكتملة.
اختبارات خدمة activation القديمة في فرع Android ليست بديلًا عن اختبارات خدمة main المنشورة، ولا ينبغي إخفاء اختلافهما.
