# rc07.33: player shutdown recovery and receiver diagnostics

When Media3 reports an error synchronously during surface detachment or release, the old session could queue a retry after its callbacks had already been cleared. The retry could run against a released player and count an intentional close as a provider failure. The session now enters a terminal closing state before detaching its output, cancels pending recovery, releases once, and ignores further play/retry requests. Preview and full-screen output detachment use that boundary.

Playback failures now report allowlisted operational details: exception class chain, HTTP status when present, Media3 timeout operation, decoder name when available, video format/profile/dimensions, Android API and device model. Raw exception messages, response bodies and credential-bearing URLs are excluded. Closing errors are tagged separately and do not affect provider format learning. Episode catalog request failures use the same diagnostics channel. Live previews are classified as live rather than unknown. The existing server schema accepts these fields in the sanitized error message.

During shutdown, release Media3 before clearing the PlayerView reference. Media3 1.6.1 release removes its surface callbacks; a subsequent view detach no longer waits for a separate surface-output acknowledgement from a stalled decoder. Both operations still run inside the closing boundary, and view cleanup runs even if release throws.

Media3 remains 1.6.1, Cronet remains 18.1.0, and decoder selection, playback transport, stream URL policy, account credentials and device activation are unchanged.

## Evidence and limits

- rc07.32 receiver telemetry contained first-frame events followed by ERROR_CODE_TIMEOUT / Unexpected runtime error. The old payload does not include the underlying timeout operation, so it cannot establish whether a particular failure occurred during playback or shutdown.
- Metadata probes using the existing emulator test accounts returned HTTP 200 and an episode list for the sampled 4K series. A subsequent managed-account MBC 1 HD probe returned TS bytes and an HLS manifest from the direct route, while the legacy gateway returned HTTP 511. These are bounded transport/metadata checks, not receiver playback validation and not evidence that every account or item works.
- Earlier emulator 4K/HDR failures identified an emulator HEVC decoder and exceeded format capabilities. That finding cannot be transferred to the physical receiver without its format/decoder evidence.
- The shutdown regression tests cover synchronous release/detach timeouts, queued retry cancellation, duplicate close, cleanup after a detach exception and preserved active playback retries on API 23 and 28. Diagnostic tests verify status/timeout/format retention without exception-message or response-body secrets.
- The receiver's reported 4K, hidden-host, episode-loading and remote-navigation symptoms still need reproduction on rc07.33. This release does not claim universal 4K/HDR support or a measured remote-navigation performance improvement.
