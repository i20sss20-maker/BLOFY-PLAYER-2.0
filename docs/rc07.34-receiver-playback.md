# rc07.34 receiver playback recovery

The rc07.33 receiver diagnostics showed `ERROR_CODE_TIMEOUT` with
`timeout=detach_surface` on Android 9 / winsat Amlogic S905X3. This occurred with
both HEVC 3840x2160 and AVC 1920x1080. The old `phase=playback` label means the
session had not entered `release()`, not that the Activity was necessarily still
visible. Playback remained allocated until `onDestroy`, after surface teardown
could already trigger the error.

## Changes

- Release the full-screen session in `onStop`, or `onPause` on Android 6 and on
  finish/back. Capture the current episode/channel, VOD position, paused state,
  track selections and recovery routes in memory; create a fresh player on return.
  Cancel pending episode navigation and zapping before releasing the old session.
- Honor provider connect/read timeouts in Cronet. When a Cronet connection cannot
  open, close it before trying the same request through the existing HTTP transport.
  Preserve request range/headers. HTTP refusals and mid-body errors are not retried
  by this transport wrapper. Provider credentials and Media3 1.6.1 remain unchanged.
- Give foreground episode detail requests a separate dispatcher and a 25-second
  total request deadline, 12-second read timeout and 5-second connect timeout. They
  previously shared the catalog client with its 90-second inactivity timeout and
  unlimited total duration. Enable transparent gzip for series details while
  preserving bulk catalog behavior and the existing 884 normalization.
- Record successful episode request elapsed time and episode count without server
  URLs or credentials, so slow successful receiver requests can be identified.

## Verification and limits

Regression coverage exercises Activity back/stop/return on API 23 and 28, restoring
the current episode rather than the original intent, paused position/track state,
single release, live-edge restart, saturated metadata queues, gzip/884 responses,
bounded stalled requests, and HTTP fallback range/headers/close ordering/refusals.
See the release verification report for actual test/build outcomes.

There is no attached adb device during this change. Receiver diagnostics confirm
the prior failures; tests cannot establish sustained physical-receiver 4K decoding
or prove the hidden subscription plays after installation. A 458/403 response is
a server refusal, not a decoder failure. The receiver must validate live preview,
full-screen live, one episode list, and 4K playback on the signed build.
